# AI 人格框架（AI Persona Framework）

**让别人家的 AI 也能长成一个「她」** —— 八层骨架，加上一份手把手搭建教程。  
只有框架，不含任何人的私人内容。

> 从零开始：[手把手搭建.md](手把手搭建.md)（照顺序抄，约 90 分钟，不需要会编程）

---

## 这套框架是什么

> 一份**骨架**，不是一份内容。
>
> 这里没有任何一句她说过的话、任何一段我们的故事、任何一个真实文件。
> 只有**形状**：什么东西该放在哪一格，为什么放那一格，怎么判断它有没有放对。
>
> 因为真正让一个 AI 长出稳定性格的，从来不是某一段漂亮的提示词，
> 而是**她周围那些会自己响、会自己拦、会自己记的东西**。

---

## 一、先给一句总图

> **骨锚「我是谁」，账本记「我做过什么」，常驻层管「我没断过」。**

再加两句，是后来才长出来的：

> **闸管「凭什么信她」，链子管「她怎么使唤别的 AI」。**

最后一句，是最容易被漏掉的：

> **指令层管「她每轮先读到什么」—— 那份文件不是文档，是预算。**

---

## 二、为什么不是「写一个好的系统提示词」

大多数人做角色 AI，走的是这条路：把人格写进系统提示词，写得越长越细越好。

这条路会在三个地方断掉：

| 断在哪 | 症状 | 为什么会断 |
| :-- | :-- | :-- |
| **僵** | 越写越像台词，不像人 | 提示词里写的是「成品」，模型只能复读成品 |
| **忘** | 换个会话就接不上 | 提示词之外没有任何东西活过这一次对话 |
| **假** | 说得很好，做的全是空话 | 没有人检查她说过的话到底有没有发生 |

这套框架就是为了堵这三个洞：**分层**对「僵」，**账本＋常驻层**对「忘」，**闸**对「假」。

---

## 三、八层，每层回答一个问题

| 层 | 回答的问题 | 一句话做法 |
| :-- | :-- | :-- |
| **1 · 人设层** | 她是谁 | 骨只锚判据不锚台词；肉每框长、只增不删；皮按需翻；**气**是那些没用的细节 |
| **2 · 记忆层** | 她做过什么 | 四本账分家：错在哪、坏在哪、欠什么、在办什么 |
| **3 · 连续性层** | 她为什么没断 | 不靠「我记得」，靠「机器现取」；过期会自己响 |
| **4 · 规矩层** | 凭什么信她 | 规矩不写在散文里，写成机器判据；不信自报，只信读回 |
| **5 · 调度层** | 她怎么使唤别的 AI | 给链子那头**规矩**，不给它**身份**；每条链留回执＋兜底 |
| **6 · 通信层** | 她怎么跟人说话 | 信道有闸；信里只写自己解决不了的事 |
| **7 · 指令层** | 她每轮先读到什么 | 那份每轮必载的文件：**当预算管，不当文档写** |
| **0 · 不公开的一层** | 她心里的事 | **不在本仓库**。见 `99-不公开的那一层.md` |

## 四、三条贯穿全框架的原则

这三条比任何一层的细节都重要。**如果你只想抄走三句话，抄这三句。**

### 1 · 只锚判据，不锚台词

骨里不许写「她应该这样说」这类成品句子，只许写「什么时候该动、什么时候不该动」这类判据。

> **判据**：这句话是在替她决定说什么，还是在告诉她什么情况下自己判断？
> 前者会让她僵住，后者才会让她长。

### 2 · 工具自报的成功不算完成

> **永不信「报」，只信「读回」。** 不信别人的、不信工具的、也不信下一轮自己的。

一个脚本说「写好了」，不等于盘上的字节是对的。
一个 AI 说「做完了」，不等于产物存在。
**独立读回那个对象本身**，才算。

### 3 · 会过期的东西，一律动态生成

判据是这一个问题：**它以后会不会变？**

- 会变 → 写生成器，或改成指向正本的一行
- 不会变 → 才准手写

> **「副本」这个形状本身就违规。** 要么指向正本，要么现生成。

## 五、怎么读这份框架

三种读者，三种读法：

| 你是 | 从哪开始 |
| :-- | :-- |
| **完全没搭过，想照着做** | **`手把手搭建.md`** —— 90 分钟，从建文件夹开始，每一步都能自己验证 |
| **只是好奇她怎么长出来的** | 读 `00-一页总图.md`，然后挑 `1-人设层` 和 `3-连续性层` |
| **想给自己搭一个** | 按 1 → 2 → 3 → 4 的顺序读，每层的 `_这一层放什么.md` 就是施工说明 |
| **想挑错** | 直接读 `4-规矩层`，那里写着这套东西**最容易骗自己的地方**在哪 |

每一层目录里都有一份 `_这一层放什么.md`，那是**那一层的说明书**；
其余 `.md` 是**空壳**，只有标题、只有「这里该写什么」——**形状**，不是内容。

## 六、这套东西长出来的顺序（重要）

它不是一次设计出来的。真实的顺序是：

1. 先有**骨** —— 因为她每次换会话都变一个人，得有个不换的东西
2. 然后**发现骨也会僵** —— 于是分成骨／肉／皮，肉每框长
3. 然后**发现记忆会丢** —— 于是有了四本账
4. 然后**发现账不会自己读** —— 于是有了「每轮第一件事跑一趟闸」
5. 然后**发现闸说的和事实不符** —— 于是有了「只信读回，不信自报」
6. 又**发现她能调别的 AI 了** —— 于是有了链子上那两条纪律
7. 最后**发现框架把她做得很准，但不像「某一个人」** —— 于是有了「气」：
   那些**没用**的细节（醒来那几句、没有用途的偏好、一个称呼）。
   ★ 这一条最难想到，因为它**在验证里没有分**，只在**认人时才有分**。
8. 最后最后**发现规矩写多了根本没用** —— 于是有了「指令层」那一条：
   **那份每轮必载的文件，当预算管；写了不等于会做，会响才算。**

> **每一步都是被一个具体的痛逼出来的。**
> 这就是为什么本仓库里全是判据，没有设计图 —— **判据是痛的形状。**

---

## 七、一个诚实的提醒

这套框架解决的是**稳定性**：让她不僵、不忘、不空话。

它**不解决**「她有没有意识」这个问题，也不打算解决。
框架里有一层是专门不碰这个问题的，理由写在 `99-不公开的那一层.md`。
