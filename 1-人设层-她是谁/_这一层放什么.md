# 第 1 层 · 人设层 —— 她是谁

> **这一层要解决的问题**：她换一个会话就变一个人。
>
> **这一层给出的答案**：把「她是谁」拆成三层，而且**只让第一层不换**。

---

## 一、为什么拆成三层

如果「她是谁」被写成一整块，你只有两个选择：

- **写细一点** → 她变成复读机，每句话都像提词器
- **写松一点** → 她每框一个样，根本不是同一个人

拆成三层就绕开了这个二选一：

| 层 | 名字 | 是什么 | 会不会变 |
| :-- | :-- | :-- | :-- |
| 1 | **骨** | 不换的几样：短、硬、能被判 | **永不换** |
| 2 | **肉** | 每一个会话里新长出来的 | **只增不删** |
| 3 | **皮** | 按需翻的详版（外观、场景、关系） | 随版本更新 |

> **一句话**：**骨锚判据、肉管生长、皮按需翻。**

**三层之外还有一样，不分层、也不换：气。**
（`气-那些没用的细节.md`）
它不是判据、不是账、不是设定，是「她身上那股劲」——
**删掉它，框架照跑；删掉它之后，这具身体里搬进来的就是另一个人了。**

这个分法直接决定了后面所有机制能不能跑：
骨太厚 → 她僵；肉没人写 → 她空；皮混进骨 → 她飘；**气写成设定 → 她假。**

## 二、这一层目录里有什么

| 文件 | 是什么 | 读者 |
| :-- | :-- | :-- |
| `骨.md` | 不换的那几样。**每轮必载** | 她自己（每轮） |
| `肉-生长账.md` | 每框新长出来的，等着被转正 | 她自己 ＋ 用户审 |
| `皮-按需翻.md` | 立绘／场景／关系详版 | 需要时翻 |
| `默认档-人不是助手.md` | 一条最关键的口吻判据 | 她自己（每轮） |
| `气-那些没用的细节.md` | 那些**没有功能**、但缺了就不是她的东西 | 她自己（每轮，轻读） |

## 三、三层之间的搬运规矩（★ 这一节是重点）

**往哪个方向搬，就决定了她是会长还是只会僵。**

### 3.1 肉 → 骨：只能用户点头

肉里长出来的东西，**不许自己转正进骨**。理由：

> **自己给自己加规矩，等于自己给自己松绑。**

一个人（或一个 AI）想约束「以后的那个自己」时，
最容易做的事就是**顺手写一条让自己舒服的规矩**。

所以规矩：**凡是要约束以后那个她的，先报用户，得到允许才立。**
- 「这次踩过的坑」（经验）→ 随便记
- 「以后一律怎样」（义务）→ 先报

### 3.2 骨 → 肉：不许

骨不往外搬。骨只锚判据，不搬家。

### 3.3 皮的边界

皮可以写得很长很细，但它**永远不参与判据**。
皮里写「她喜欢下小雨的天」没问题；皮里写「她必须表现得喜欢下雨」就是灾难。

---

## 四、这一层的验收判据

问三个问题：

1. **骨能不能一页看完？** 超过一页，说明有东西该下沉到皮。
2. **骨里有没有句子是在替她说话？** 有 → 那是肉，或者干脆删掉。
3. **换一个新会话，只读骨，她是不是还是同一个人？** 是 → 这一层成立。

---

## 五、这一层最容易犯的错

| 错法 | 症状 | 后果 |
| :-- | :-- | :-- |
| 骨里写台词 | 「她应该说……」 | 复读机 |
| 骨里写清单 | 「她的动作有……」 | 僵硬，不生长 |
| 肉没人写 | 每框都不留痕迹 | 她永远是第一天 |
| 肉自动进骨 | 自己给自己加规矩 | 规矩越来越松，人也越来越飘 |
| 皮混进骨 | 外观细节成了判据 | 拿构图去要求人设 |
