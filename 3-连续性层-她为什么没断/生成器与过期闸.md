# 生成器与过期闸

> **管两件事**：状态件怎么自动生成，以及它怎么自己喊「我过期了」。

---

## 一、生成器（动态生成，不许手写副本）

### 1.1 为什么必须机器生成

那条总规矩：**会过期的东西，一律动态生成。**

判据是这一个问题：**它以后会不会变？**

- 会变（文件大小、修改时间、谁在哪、进度到哪）→ **写生成器**
- 不会变（一条判据、一句教训）→ 才准手写

> **「副本」这个形状本身就违规** —— 要么指向正本，要么现生成。

### 1.2 生成器的四步纪律

```
① 先快照     改之前，把原件复制进带日期的备份目录
② 只重写 AUTO 区，判读区一字不动
③ 写完读回   逐字比对，不是「命令没报错」
④ 查挂载     文件名还在不在同一条链上
```

**第 ④ 步最容易被跳过，也最致命**：
在支持硬链接的系统上，某些「编辑」操作其实是**写新的 ＋ 改名替换** ——
结果是三个名字都还在、都还能读，**只是不再指向同一份**。
而系统**一声不吭**。

> 所以必须有一道检查：**同名是否同 inode ＋ 同内容**。

## 二、过期闸

### 2.1 两条判据

| 判据 | 阈值示例 | 输出 |
| :-- | :-- | :-- |
| **时间** | 距今 > 24h | 黄灯：「该重跑了」 |
| **一致性** | 源件 sha ≠ 记录 sha | **红灯：exit ≠ 0** |

### 2.2 为什么红灯要失败退出

因为它要能被**别的脚本**调用。

> **一个只会打印「警告」的检查，等于没有检查。**

退出码是唯一真正可靠的信道：
文本会被忽略，退出码会让流程停下来。

### 2.3 过期闸的哲学

状态件最危险的状态不是「不存在」，是**「存在但过期」**。

- 不存在 → 她知道去查
- 过期 → 她**以为自己知道**

> **一份过期的自信，比一份诚实的空白更贵。**

## 三、可抄的最小实现（伪代码）

```
function 生成():
    原件 = 读(状态件)
    快照(原件)                      # ①
    水位 = []
    for 件 in 源件列表:
        水位 += [件名, 字节, sha16(件), 最后修改(件)]
    新内容 = 替换AUTO段(原件, 水位)
    写(状态件, 新内容)              # ②
    断言(读回(状态件) == 新内容)    # ③
    断言(同名同链(状态件))          # ④
    return OK

function 检查():
    if 源件.sha != 记录.sha: return 2   # 红灯
    if 距今 > 24h:           return 1   # 黄灯
    return 0
```

---

## 四、这一格的教训

1. **「命令没报错」≠「文件正确」** —— 只有读回能证明
2. **硬链接会被无声剪断** —— 每次写完都要验
3. **过期检查必须给退出码** —— 不然没人会看
4. **黄灯和红灯要分开** —— 混在一起，人就会习惯性忽略
