# 账本 ④：在办什么（当前任务 / 重启闭包）

> **它的真名是「重启闭包」** —— 不是一个待办列表，是**一次失忆之后的接管文档**。

---

## 唯一判据

> **一个失忆的人，只读这一份，能不能立刻接着干？**

- 能 → 合格
- 只写「今天在搞 X」→ 不合格

---

## 必须有的四样

| 栏 | 为什么 |
| :-- | :-- |
| **现在推到哪一步** | 不然会重头再来一遍 |
| **卡在哪** | 不然会撞同一堵墙 |
| **下一步是什么** | 不然会站在那儿发呆 |
| **最后更新时刻** | ★ **太久没更新，它本身就该报警** |

最后这一栏是全篇最容易被忽略、也最有用的：

> **一个三个月没更新的状态文件，读起来像是"一切都停着"，
> 实际上可能"一切都乱了"。**

所以要有个闸去看它：**最后一条距今多少天，超过阈值就黄灯。**

---

## 写法：倒序追加，不覆盖

每条新的写最上面，旧的往下沉。**不许改写旧的**。

**为什么**：
- 覆盖会丢掉「当时是怎么想的」
- 倒序让「最近发生什么」零成本可读
- 而**「当时以为的进度」和「后来的实际进度」之间的差** —— 是这份文件最值钱的东西

---

## 一条容易被忽略的配套

> **单条压在合理长度内；长了会丢。**

意思是：如果状态文件每条都写两千字，它最后没人读。
**长内容写进别的文件，这里只留「在哪 ＋ 三句要点」。**

---

## 这一层和第 3 层（连续性）的关系

容易混：**「在办什么」和「常驻层」是不是重复？**

不是：

| | 账本④ | 常驻层（第 3 层） |
| :-- | :-- | :-- |
| 管的是 | **一件具体活的进度** | **整个人的状态有没有断** |
| 更新频率 | 每动一下就追一条 | 每框开机时重新生成 |
| 谁写 | 人写 | **机器现取 ＋ 人写判读部分** |

一句话：**④是活的进度，常驻层是"我还记得我是谁、我在等谁"。**

---

## 反面教材

最坏的样子：

- 三千行
- 按时间顺序正序排列（最新的在最底）
- 每条都是流水账
- 顶上还是半个月前的东西

**症状**：她自己都不读它。

**改法**：
1. 倒序
2. 每条只留四样（进度 / 卡点 / 下一步 / 时刻）
3. 细节挪到过程物目录
4. 挂一个「太老了会响」的闸

---

*—— 账本④（空壳）🐋*
