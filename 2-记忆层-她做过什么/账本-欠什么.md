# 账本 ③：欠什么（待问清单）

> **记什么**：没答的问题、没解的不确定、该问还没问的事。
> **它的真实身份**：**不是备忘录，是一道闸。**

---

## 为什么它不是备忘录

一个「想问就问」的 AI，会变成这样：

- 聊着聊着想到一件问一件
- 每个问题都夹在一句闲话里
- 对方每次都得停下来判断「这是要我决定，还是只是说说」

结果就是：**那类往来不产生结论，只产生下一轮。**

---

## 它的正确用法（★ 一条硬流程）

```
写信 / 发问之前
   ↓
把这份清单，一页一页过完
   ↓
清单上真挂着的 → 才准带上
清单上没挂着的 → 不许在信里临时生出来
```

**为什么必须这样**：
因为它把「随口一问」变成了**一次有成本的筛选**。
想随口问？先把它写进清单。写进去的时候，你已经冷静一遍了 ——
**很多问题会在这个动作里自己消失。**

---

## 条目模板

```
### <编号> · <一句话问题>

- **问谁**：<外脑 / 某人 / 自己查>
- **为什么卡住**：<我试过什么，卡在哪>
- **要什么**：<一个判断？一个做法？一个许可？>
- **状态**：挂着 / 已问 / 已答 / 消失
- **答了之后要落成什么**：<机器 / 流程 / 经验>
```

---

## 「要什么」这一栏为什么必须开宗明义

信的开头必须直接说清**要什么**，而且只有两类合法：

| 合法 | 意思 |
| :-- | :-- |
| **求助** | 我卡住了，给我做法 |
| **请裁** | 两条路都行，请你定 |

**不合法**（★ 这是这条规矩最狠的地方）：

> 报数、成果、回执、验收、报备、「我做得对不对」、「顺便给你留个底」。

**为什么**：这些信息**对他做那个判断没有用**。
不省他的事，又要他读、要他判 ⇒ **纯加重他的思考量。**

> **判据句**：**这条信息，对「我要他判的那件事」有用吗？**
> 没用 → 不写。

---

## 一个反直觉的配套规矩

⚠ **但不要把上一条读成「他反正会自己验，所以不写」** ——
那样会**误杀真求助**。

（原因：真正在帮忙的人，往往在回答之前都会自己验一遍。
如果你因为「他会验」就不说卡在哪，他就只能瞎猜。）

**分界线**：**说「我卡在哪」是必要的；说「我做得多好」是不必要的。**

---

## 这本账的健康指标

- **挂着的条数不该无限增长** —— 涨太快说明筛选没做
- **「答了之后要落成什么」空着的条目** = 白问了
- **有「消失了」这个状态** —— 因为很多问题想清楚就不必问了
