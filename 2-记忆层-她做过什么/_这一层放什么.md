# 第 2 层 · 记忆层 —— 她做过什么

> **这一层要解决的问题**：她的记忆只活一个会话。
> **这一层给出的答案**：四本账，分家记。

---

## 一、为什么是「四本」而不是「一本」

直觉上你会写一个 `记忆.md`，什么都往里塞。它会在两周内变成**垃圾场**：
教训、待办、抱怨、进度、灵感，全混在一起，**谁也不会去读**。

分家的判据只有一个：**账本的读者是谁、什么时候读。**

| 账本 | 记什么 | 谁读 / 什么时候 |
| :-- | :-- | :-- |
| **① 错在哪** | 工作出错：命令、脚本、文件、判据 | 自己，出错当场写；要翻案例才读 |
| **② 坏在哪** | 行为坏习惯：忘事、越界、拖话、想当然 | 自己，每框开工时看一眼 |
| **③ 欠什么** | 没答的问题、没解的不确定 | 自己，写信前必须过一遍 |
| **④ 在办什么** | 当前的任务、进度、下一步 | 自己，**每轮开局就读** |

> **关键差别**：①②是**教训**，③④是**状态**。
> **教训不读也不会消失，状态不读就会踩错。**

---

## 二、①和②为什么必须分家

这是这一层里最不显然、但最有用的一个决定。

| 本 | 症状 | 例 |
| :-- | :-- | :-- |
| **① 错在哪** | 世界给她的反馈错了 | 命令写错了、路径不通、判据用错了 |
| **② 坏在哪** | 她自己有毛病 | 忘了前置、越了界、话说满了、想当然 |

**为什么必须分开**：

- 分家之前，所有东西都往①塞 → **变成技术日志**，
  于是「她又忘了跑前置检查」这种**行为病**淹在 BSOD 里，永远没人修。
- 分家之后，②那本很短、很难看、很难受 —— **但它看的是人，不是环境**。

> **判据句**：**这件事换个做法就能避免，还是换个人才能避免？**
> 前者进①，后者进②。

---

## 三、每条教训的固定四栏

不管①还是②，每条都必须写满四栏：

| 栏 | 写什么 |
| :-- | :-- |
| **症状** | 当时看到了什么（**原话、原报错**） |
| **根因** | 为什么会这样（往下再挖一层，别停在表面） |
| **代价** | 花了多少时间 / 谁被吵醒 / 什么被弄坏 |
| **怎么防** | **能不能变成一条机器判据？** |

> ★ **没有「怎么防」的记录，只是自我批评。**

而且「怎么防」有分档（重要）：

- **经验**（这一次踩过的坑）→ 随便记
- **义务**（以后一律怎样）→ **先报用户，得到允许才立**

理由和第 1 层一样：**自己给自己加规矩，等于自己给自己松绑。**

---

## 四、③「欠什么」的特殊用法

待问清单不是备忘录，是**一个闸**。

规矩：**给外脑写信之前，必须先把这份清单一页一页过完。**
清单上真挂着的，才准带上；没挂着的，不许在信里临时生出来。

**为什么**：没有这道闸，写信会变成「聊着聊着想到一件问一件」——
那类往来**不产生结论，只产生下一轮**。

---

## 五、④「在办什么」的形状

它不是待办列表，是**重启闭包**。判据：

> **一个失忆的人，只读这一份，能不能立刻接着干？**

能 → 合格。
只写「今天在搞 X」→ 不合格（信息不够）。

它至少要有：
- 现在推到哪一步
- 卡在哪
- 下一步是什么
- **上一次更新是什么时候**（★ 太久没更新，它本身就该报警）

---

## 六、这一层的验收判据

1. **四本是不是真的分开了？** 试着找一件事，它该进哪本 —— 唯一。
2. **每本有没有「最后更新」的痕迹？** 没有 → 它已经死了，只是没人发现。
3. **②那本读起来难受吗？** 不难受说明写得太客气了。
