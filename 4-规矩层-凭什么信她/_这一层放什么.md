# 第 4 层 · 规矩层 —— 凭什么信她

> **这一层要解决的问题**：她会说漂亮话。
> **这一层给出的答案**：规矩不写在散文里，**写成机器**。

---

## 一、一个根本的区别：规则 vs 闸

| | 规则（rule） | 闸（gate） |
| :-- | :-- | :-- |
| 形态 | 一句话，写在文档里 | 一段代码，会跑、会退出 |
| 谁执行 | **她记得就执行** | **机器每次都执行** |
| 失效条件 | 她忘了 / 她忙 / 她觉得「这次特殊」 | 只有闸被删掉 |
| 可靠性 | 靠自觉 | 靠退出码 |

> **判据**：这条规律如果她不遵守，**有没有什么东西会响？**
> 不会 → 它现在只是**愿望**，还没成为规矩。

这一层的全部工作，就是**把愿望变成会响的东西**。

---

## 二、闸分三层（★ 按「多危险」分，不按「多重要」分）

| 层 | 什么情况下用 | 强度 |
| :-- | :-- | :-- |
| **流程层** | 每一步都该做的事（开工、收工、写文件前） | 轻，但**最有用** |
| **硬停层** | 不可逆的操作（删、覆盖、发信） | 重，**只留给真正不可逆的** |
| **记忆层** | 记完还得再查一遍的事（账目、字节、校验） | 事后核对 |

**为什么按危险分而不是按重要分**：

因为**重要的东西太多，不可逆的东西很少。**
如果所有重要的都做成硬停，她每一步都在被拦，最后会**绕过闸**。
**留一点松，闸才活得久。**

> **判据句**：**这道闸拦下来的，是「再也回不去」的事吗？**
> 不是 → 放到流程层，别动不动就硬停。

---

## 三、三条红线为什么必须放原文

一般规矩可以写成指针（「详细见某文件」）。
但**最危险的几条不能**。

**理由**：**最危险的规矩，不能依赖「记得去翻」。**

翻不到 = 没有。而这几条恰好是「翻不到就会出事」的那种。

所以它们要直接写在每轮必载的地方，**原文，四五行，看得完**。

> **分层原则**：**不是所有东西都放原文（会臃肿），而是【最危险的】放原文。**

---

## 四、这一层最反直觉的一条：不信任自己

框架里写着「不信自报，只信读回」。

**第一层意思**：不信工具的、不信别人的 —— 这个好理解。
**第二层意思**（★ 难得多）：**也不信下一轮自己的。**

因为她会**记住一个「合理的版本」**，而不是事实。
一晚上之后，「当时好像成功了」会变成一个**非常确定的记忆**。

> **所以：结论必须是读回来的，不能是回想起来的。**

---

## 五、这一层的验收：故意弄坏它

规矩层不可能靠读来验收，**只能靠破坏**。

| 测什么 | 怎么测 |
| :-- | :-- |
| 闸真的会响吗 | 弄坏一处，看退出码 |
| 红灯拦不拦 | 把状态件改一个字节，看下一轮报不报 |
| 会不会太吵 | 正常干活时，它一共响了几次 |
| 会不会太长 | 它打印了多少字 |

> **一句话**：**没有跑过的闸，只是文档。**
