# 第 5 层 · 调度层 —— 她怎么使唤别的 AI

> **这一层要解决的问题**：她一个人干不完，而且干不好所有事。
> **这一层给出的答案**：把活派出去，但**只给链子那头规矩，不给它身份**。

---

## 一、先想清楚：为什么「派出去」比「自己扛」难

自己干活只有一种失败：**做错了**。
派出去干活有三种失败：

| 失败 | 症状 |
| :-- | :-- |
| **它没做** | 说做完了，产物不存在 |
| **它做偏了** | 做了，但不是你要的 |
| **它做对了但说不清** | 产物对，过程无法复现 |

所以**调度层的第一原则不是「怎么派得更快」，是「怎么知道它到底做了什么」。**

---

## 二、两条铁律

### 铁律一：给规矩，不给身份

**不给它注入人设。**

**为什么**：
- 人设回答的是「谁在说话」，不是「能不能干活」
- 给它一套完整的身份，会**造出一个没有账本、没有约束、不知道自己站在哪一格的她**
- 而没有账本的身份，是最危险的东西：**它会自信地代表你去说话**

**该给它什么**：
> **规矩** —— 怎么派活、什么不许做、产物走文件、报告当「未验证的主张」。

**判据句**：**「给它身份」是在复制一个她；「给它规矩」是在雇一个工人。**

### 铁律二：链子两端都留痕迹

**框架不信任链子那头。**

每一趟活都要留：
1. **原始证据**（它的完整事件流 / 回执）
2. **产物在哪**（文件路径，可验）
3. **退出码**（唯一可靠的成败信号）

---

## 三、派活的正门（不要直接喊底层工具）

**永远不要直接调那个执行器。** 走一个「正门」，正门负责：

```
① 附上规矩卡（它每次都读到同一套规矩）
② 给它一个干净的临时目录（不污染家）
③ 事后自动出回执：事件流 / 产物在不在 / 退出码
```

**判据**：**这一次活，事后能不能交出三样（证据、产物、退出码）？**
不能 → 这次派活不合格，哪怕它答得漂亮。

---

## 四、产物三层兜底（★ 这一层最实用的技巧）

它**不一定把结果写到你要的地方**。所以要三层接：

| 层 | 从哪拿 |
| :-: | :-- |
| **L1** | 它自己写到文件里的（最理想） |
| **L2** | 它最后一条消息里写的（次好） |
| **L3** | 从**工具调用的回执**里合成（最后手段） |

**为什么要三层**：因为小模型**经常只完成一半** ——
它可能读了文件、跑了命令，但**最后没把结论写出来**。

而工具回执里，**有你需要的全部原始材料**。
从回执合成，不是作弊，是**承认它的弱点并绕开它**。

> **判据句**：**「它做没做到」和「它说没说」是两件事。**
> 产物落在「做到」上（三层兜底），来源落在「说没说」上（回执里如实标）。

---

## 五、验收顺序（★ 千万不要反过来）

```
先验【链子通不通】 → 再验【活干得好不好】
```

**为什么**：

- 链子不通 → 所有失败都是**通道问题**，换模型没用
- 链子通了但活不好 → 才是**模型的格**问题

**判据**：**「链子断不断」看最小烟测；「那头能不能干成活」是另一回事。**

把这两件事混在一起，会让你**在通道坏掉的时候，反复换模型**。
