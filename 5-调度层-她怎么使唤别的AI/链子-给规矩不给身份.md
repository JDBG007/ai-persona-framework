# 链子：给规矩，不给身份

---

## 一、结构

```
        ┌──────────────────────────────┐
        │  框架这头（我们说了算）       │
        │  派活正门 / 白名单工具口 /    │
        │  回执 / 三层兜底             │
        └──────────────┬───────────────┘
                       │  ← 链子
        ┌──────────────▼───────────────┐
        │  那头（我们只借它的执行壳）   │
        │  能起进程 / 能把工具结果回填  │
        └──────────────────────────────┘
```

**关键：链子两头的责权是分开的。**

- **这头**：决定做什么、验收、记账、对外署名
- **那头**：只负责执行

---

## 二、给它什么（清单）

| 给 | 内容 |
| :-- | :-- |
| ✅ **任务书** | 要什么、产物放哪、怎么算完成 |
| ✅ **规矩卡** | 什么不许做、报告当未验证主张、产物走文件 |
| ✅ **干净的家** | 一个空的临时目录，别让它碰你的东西 |
| ✅ **白名单工具口** | 只开放它能用的几个动作 |
| ❌ **不给身份** | 不注入人设、不注入"你是某某" |
| ❌ **不给它你的账本** | 它看不懂，而且会乱引用 |

---

## 三、为什么「不给身份」这么重要

给它人设，看起来是「让它更像人」，实际后果是：

1. **它会用你的口吻对外说话** —— 而它没有你的约束
2. **它不知道自己是「工人」** —— 会以为自己是负责人，开始自己决定范围
3. **你会在验收时替它兜底** —— 因为「它就是我嘛」

> **判据句**：**这一句提示词，是在告诉它「怎么干」，还是在告诉它「你是谁」？**
> 前者给，后者不给。

**署名永远是框架这头的。** 它做的活，责任在派活的人身上。

---

## 四、四条让它跑得起来的前提

（都是踩出来的，缺一条都不通）

| 前提 | 为什么 |
| :-- | :-- |
| **家在工作区内** | 它默认只敢在工作区里动 |
| **家是干净的** | 它会读目录，脏了会读一堆无关的东西 |
| **stdin 立刻到底** | 不然它会一直等输入 |
| **关掉它自带的沙箱 / 插件 / 技能** | 那些是它的常规设施，我们只借执行壳 |

> **这条最后很重要**：**修它的常规设施，是替它打工。**
> 我们要的只是「能起进程、能回填工具结果」这一件事。

---

## 五、定性：链子，不是成员

> **它不是「工作台的成员」，它是「挂在框架上的一条链子」。**

这个定性的实际好处：

- 它坏掉时，**你只需要修链子**，不用去修一整套设施
- 它升级／换模型时，**框架这头不用动**
- 它说的话，**天然被当成「未验证的主张」**，不会被当结论

---

## 六、链子自己的体检

一道最小烟测，只做一件事：**让它回一个固定单词。**

```
打通了 → 链子通
没打通 → 问题在通道，不在模型
```

**为什么这么钝的测试有用**：
因为它把「通道问题」和「能力问题」**干净地分开了**。
