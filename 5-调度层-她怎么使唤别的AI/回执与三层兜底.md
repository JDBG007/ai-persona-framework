# 回执与三层兜底

> **一句话**：**它做得对不对，你不能问它，只能看盘。**

---

## 一、每趟活必须交出的三样

| # | 交什么 | 为什么 |
| :-: | :-- | :-- |
| 1 | **原始事件流** | 事后复盘靠它，不靠回忆 |
| 2 | **产物在哪** | 可验、可读回、可 diff |
| 3 | **退出码** | 唯一可靠的成败信号 |

**缺任何一样，这趟活就没有「完成」，只有「据说完成了」。**

---

## 二、三层兜底

### L1 · 它自己写的产物（最理想）

直接读文件，验内容。

### L2 · 它最后一条消息

它可能没写文件，但在最后一条消息里把结论说了。
→ 从消息里抽出结论，**落成文件**。

### L3 · 从工具回执合成（最后手段）

它可能没写、没说，但**它跑过的每个命令都有记录**。

→ 从回执里把「读了什么、跑了什么、输出了什么」**按顺序拼起来**。

**这不是编造，这是承认它的弱点并绕开它。**

> 真实观察：小模型常常做到一半就停 ——
> 读了文件、跑了命令，**但最后没把结论写出来**。
> 这时 L3 是你唯一能拿到结果的地方。

---

## 三、为什么必须区分「做到」和「说没说」

| 问题 | 看哪 |
| :-- | :-- |
| **它做没做到** | 产物（L1／L2／L3） |
| **它说没说** | 回执里如实标注来源层级 |

**为什么不能混**：

如果你把 L3 合成的产物当成 L1（它自己写的），
**下次你就不敢信任何东西了**。

> **判据**：**回执里必须能看出「这个结论是从哪一层来的」。**

---

## 四、回执模板

```
任务：<一句话>
时间：<起 / 止>
退出码：<>

证据：
  事件流：<路径，字节数>
  工具调用次数：<n>，每次退出码：<列表或汇总>

产物：
  来源层级：L1 / L2 / L3
  路径：<...>
  读回校验：<字节数 / sha / 关键内容比对结果>

异常：
  <它卡住的地方 / 报错 / 超时>
```

---

## 五、一条最实用的经验

> **不要因为它「说得头头是道」就以为它做了。**

一个模型编造一份完美的报告，成本几乎为零。
而**盘上的字节，编不出来**。

所以：**先读盘，再读话。**
顺序反了，你会被说服。

---

## 六、验收顺序（再强调一次）

```
① 链子通不通？（最小烟测）
② 这趟活完成了没？（产物 ＋ 退出码）
③ 完成得好不好？（内容质量）
```

**①不过，后面全是白搭。**
**③永远最后。** 因为它最容易让你放弃①和②。
