# 每轮必载的那份文件（空壳）

> 这是一份**结构示范**，不是一份可以照抄的内容。
> 每一节都只给"这里该放什么"，不放任何真实规矩。

---

## 一、开工顺序（写在最前面）

**原因**：她每一轮**第一件事**做什么，决定了她会不会跳过前置直接干活。

这里写的是**一个顺序**，不是一份清单：

```
1. 跑前置检查（跑什么、不跑不许开工）
2. 加载工具/断言函数
3. 要想动手 → 先说清"我怎么知道做对了"
4. 写完/改完 → 读回那个对象本身
```

**判据**：这一节要短到**她能一口气执行完**。
如果它需要"读三遍才明白先做啥"，它就已经失效了。

---

## 二、红线（放原文，不靠指针）

**为什么放原文**：最危险的几条，**不该依赖"记得去翻"**。

放三到五条，每条一句，句式统一：

```
1. 往「可能已有内容」的目标写东西 → 先清空 ＋ 写完读回逐字校验
2. 判断存在/成功 → 读那个对象本身，不信工具返回值
3. 动窗口 → 不许改大小或最大化状态
```

**判据**：一条红线如果**需要解释才懂**，它就不该在这里 —— 它该去闸里。

---

## 三、行为的底线

这里放**她每天都会用到、但不会自然遵守**的那几条。

典型三类：

- **不许静默**（调工具前先写一句人话：现在干什么、为什么）
- **称呼固定**（对谁用什么称呼，不许混）
- **落款固定**（谁的账，谁的记号）

**判据**：这条如果她不遵守，用户会不会**当场感觉到**？
感觉不到的，别放这儿（放哪儿都没用）。

---

## 四、发现问题时的三步

一个固定动作序列，写死，不让她临场想：

```
① 当场记（哪个本子，不隔夜）
② 不知道怎么分类 → 先随便贴个代号，标"待归"（绝不许因为"归到哪不确定"就停下）
③ 带着已经写下来的东西去请教（别自己闷头分类）
```

**为什么这一节重要**：
它治的是「**一遇分类不确定就停住**」这个病。
**顺序不能换** —— 先写下、再分类、再请教。反过来就会卡在第一格。

---

## 五、什么直接做，什么先报

一个判断表，两列就够：

| 情形 | 怎么办 |
| :-- | :-- |
| 过期路径 / 指针漂了 / 链接指错 | **直接改**（机械、有明确正解、错了也能回头） |
| 骨 / 规矩 / 权限 / 不可逆 / 机制改动 | **才上报** |

**判据挂一句话在最后**：

> **「别加重对方的思考量。」**
> 手要停下来问之前，先答一句：「这件是不是显然该做、且有明确正解？」是 → 做，别问；不是 → 问。

**为什么这条必须写主动作里**：
它防的是「**该拍板的不拍、明知该做还去问**」——
那不是谨慎，那是把判断成本转嫁给别人。

---

## 六、收工（固定三样，不许膨胀）

**收工只写三样**，不要再加：

1. **今天真正变了什么**（只列会改变以后行为的）
2. **欠着什么**（挂着没办的）
3. **要对方批什么**（一件就好）

**为什么定死三样**：
收工报告最容易变成一个「成绩汇报」，而汇报**不产生结论，只产生下一轮**。
三样足够，多一样都是负担。

---

## 七、指路（这一节是"指针"，不是"正文"）

这一份到最后应该变成一张**极短的路牌**：

| 遇到什么 | 去读哪个 |
| :-- | :-- |
| 前置规则 / 不变量 | `RULES.md` |
| 断言函数 | `工具箱.ps1` |
| 发消息的通道 | `发消息.ps1` |
| 复算口径 | `自证串口径.md` |

**只写一行一条**，不要写"它是什么"。

---

## 八、这一节永远在最后：校准日期

```
最后校准：YYYY-MM-DD（改这份文件时，顺手把它改成当天）
```

**这一行必须由机器写，或至少由人每次改文件时顺手改。**
它是这份文件的"心跳" —— **一个不跳的日期，说明这份文件已经在骗人了。**
